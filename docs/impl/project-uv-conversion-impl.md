# Project UV Conversion Implementation Notes

## Scope

Convert dependency management and project commands to `uv` while preserving behavior.

This work should not change translation logic, UI behavior, CLI flags, tests, fixture contents, or OpenAI model behavior
except where command invocation changes from `PYTHONPATH=src ...` to `uv run ...`.

## Dependency Audit Rules

- Include only direct runtime imports in `[project.dependencies]`.
- Put formatter, type checker, and browser test runner in `dependency-groups.dev`.
- Do not include transitive dependencies from `requirements.txt` unless a source file imports them directly.
- Do not upgrade packages as part of the initial migration unless uv cannot resolve the existing exact pins.
- If uv resolution forces a version change, document the package, old version, new version, and reason in this file.
- Transitive dependencies may differ from the old frozen `requirements.txt`; validation determines whether any
  transitive package needs to become an explicit direct pin.

Current resolution note:

- `uv lock` resolved all direct runtime and dev pins exactly as requested.
- Dependency refresh updated direct runtime pins to their latest stable PyPI releases where newer versions were available.
- `pip==26.1.1` is a dev dependency so the synced audit environment does not retain the vulnerable `pip==24.0`
  virtualenv seed package.
- `uv sync` changed multiple transitive packages compared with the old frozen `requirements.txt`; all current direct
  dependency pins are exact.
- `pip list --outdated` reports `pydantic_core 2.46.4` with `2.47.0` available, but `pydantic==2.13.4` requires
  `pydantic-core==2.46.4`; do not override that transitive pin outside a compatible `pydantic` release.

## Implementation Steps

1. Verify uv is available.
   - Run `uv --version`.
   - If missing, install uv using an official method before changing project files.

2. Add project metadata.
   - Create `pyproject.toml`.
   - Add exact runtime dependencies.
   - Add exact dev dependencies.
   - Add `xlsx-translate` console script.
   - Add setuptools build backend and package discovery for `src`.
   - Add `.python-version` with `3.11`.

3. Generate and verify the lockfile.
   - Run `uv lock`.
   - Run `uv sync`.
   - Confirm `uv.lock` is created and `.venv` remains ignored.

4. Update project commands.
   - Update `README.md` installation, CLI, UI, and test sections.
   - Update `AGENTS.md` common commands.
   - Replace `PYTHONPATH=src` examples with `uv run`.

5. Update tests and command assumptions if needed.
   - Prefer subprocess calls through `uv run xlsx-translate` for CLI behavior.
   - Keep direct Python module invocations only when a test explicitly needs them.
   - Avoid changing test assertions unrelated to command invocation.

6. Remove legacy dependency source.
   - Delete `requirements.txt` after `uv sync` and validation pass.
   - Do not keep two dependency sources unless a deployment requirement is documented.

7. Validate.
   - Run formatting.
   - Run type checking.
   - Run the full unittest suite.
   - Run CLI smoke checks.
   - Run Streamlit smoke or browser-backed UI tests.

## Validation Commands

Use these commands after implementation:

```bash
uv --version
uv lock
uv sync
uv run black src tests
uv run pyright
uv run python -m unittest discover -s tests
uv run xlsx-translate --help
uv run xlsx-translate --root ./resources/test_fixtures/sample.xlsx --source ja --target en --estimate
uv run streamlit run src/app/streamlit_app.py
uvx pip-audit --path .venv/lib/python3.11/site-packages --skip-editable --progress-spinner off
```

The Streamlit command is interactive. If the browser-backed UI tests are available, prefer them over a manual smoke test.

## Rollback Plan

If `uv` resolution or package installation fails:

- Restore `requirements.txt` from git.
- Remove `pyproject.toml`, `uv.lock`, and `.python-version`.
- Revert README and AGENTS command changes.
- Keep any findings in this implementation doc before reverting so the next attempt has concrete failure context.
